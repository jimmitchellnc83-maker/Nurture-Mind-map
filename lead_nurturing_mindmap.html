Core Properties (10 Custom Fields)

▼

Custom fields that manage nurture logic, progression tracking, and CRM alignment.

📊 track_current
Dropdown: Awareness, Research, Qualification, Hot
Controls the active nurture stream for each contact. Determines which content track the contact is currently enrolled in based on their engagement level.
📍 track_checkpoint
Number
Stores the index of the next module to send within the current track. Enables contacts to resume exactly where they left off after pauses.
🏆 highest_track_reached
Dropdown
Prevents regression or restarts by recording the highest track a contact has entered. Ensures contacts never move backward in the nurture journey.
⚙️ track_state
Dropdown: Active, Paused, Completed
Determines whether nurture sequences are currently running. Controls the overall execution state of nurture automation for each contact.
📝 track_reason
Text
Documents why a track is paused, resumed, or changed. Provides audit trail and context for nurture status changes.
🔄 crm_lifecycle_stage
Dropdown
Mirrors the lifecycle status of the contact or account in the CRM. Keeps marketing automation synchronized with sales stages.
💼 crm_open_opportunity
Boolean: Yes/No
Indicates whether an active deal is associated with the contact. Used to pause nurture when sales is actively working the opportunity.
📅 reentry_eligibility_date
Date
Sets a future date for re-engagement after a disqualification or recycle event. Prevents premature re-nurturing of recycled leads.
📈 score_current
Number
Reflects the most recent engagement or behavior-based lead score. Used to determine track progression and qualification status.
⚡ velocity_7d
Number
Measures engagement acceleration over a rolling 7-day period for trigger logic. Identifies contacts with increasing engagement momentum.

Automated Workflows (4 Core Systems)

▼

Four automation sequences that govern progression, pausing, and re-entry across the nurture lifecycle.

🎯 Workflow A: Track Management
Automatically advance or adjust nurture tracks based on engagement level and behavioral signals

TRIGGERS:

  • Property changes
  • Form submissions
  • Page views
  • Content downloads
  • New engagement events

ACTIONS:

  • Update track_current based on score bands
  • Set or update highest_track_reached
  • Ensure contact remains enrolled only if track_state = Active
🔐 Workflow B: CRM Status Control
Ensure nurture communications stop when sales ownership begins, auto-resume when returning to marketing-qualified

TRIGGERS:

  • Lifecycle stage updates in CRM
  • Deal creation or closure

ACTIONS:

  • Pause nurture if contact becomes SQL, has open opportunity, or converts to customer (track_state → Paused)
  • Set reentry_eligibility_date if disqualified or recycled
🔄 Workflow C: Re-entry Logic
Reactivate and re-enroll contacts in their most recent track at the saved checkpoint

TRIGGERS:

  • Lifecycle returning to marketing-qualified
  • Recycle status after pause period

CONDITIONS:

  • reentry_eligibility_date reached
  • crm_open_opportunity = false

ACTIONS:

  • Reactivate (track_state → Active)
  • Re-enroll in most recent track at saved checkpoint
✅ Workflow D: Checkpoint Tracking
Maintain continuity so contacts resume exactly where they left off if paused or re-enrolled

TRIGGERS:

  • Successful delivery of nurture message
  • Completion of content module

ACTIONS:

  • Increase track_checkpoint by 1
  • If index exceeds available modules, mark track as Completed

3
Track Checkpoint Resumption Logic

▼

System design ensuring contacts never restart from the beginning, preserving continuity through pauses, ownership changes, or lifecycle transitions.

📌 Module Reference System
Each nurture message references the track_checkpoint value to determine which module is next. The checkpoint acts as a pointer to the contact's exact position in the nurture sequence.
➕ Increment After Each Send
After each successful send, the system automatically increments track_checkpoint by one. This ensures the next message delivery picks up at the correct next module.
⏸️ Automatic Stop Conditions
Progression automatically stops if track_state = Paused or lifecycle indicates an open deal. This prevents nurture messages from being sent while sales is actively working the opportunity.
🔄 Smart Resume Logic
When reactivated, the automation resumes from the saved checkpoint value without resetting progress. Contacts continue from their last position, maintaining journey continuity.

4
CRM Synchronization & Automation Triggers

▼

Bidirectional synchronization managing lifecycle stages, deal triggers, sales pauses, and recycle logic.

🔄 Lifecycle Synchronization
The CRM's lifecycle status updates the crm_lifecycle_stage field automatically through bidirectional sync. This ensures marketing automation always reflects the most current sales status.
💼 Deal Triggers
Deal creation or closure updates the crm_open_opportunity field to control whether nurture is paused or resumed. When a deal opens, nurture stops; when it closes, re-entry logic evaluates.
⏸️ Sales Pause Automation
When the lifecycle stage indicates sales ownership (SQL, Opportunity, or Customer), the system automatically sets track_state = Paused to prevent nurture interference.
♻️ Recycle & Re-entry
If the lifecycle stage changes to Recycle or Closed-Lost, the system waits until reentry_eligibility_date, then sets track_state = Active to resume the correct track at its saved checkpoint.

5
Data Reliability & Continuity Safeguards

▼

Safeguards preventing data loss, duplication, looping, and premature restarts of nurture sequences.

💾 Persistent Properties
All key property values remain persistent even when a contact exits automation. Critical fields like track_checkpoint and highest_track_reached are never lost.
🔒 No Automatic Clearing
The system never clears track_checkpoint or highest_track_reached unless manually reset. This ensures contacts can always resume from their correct position.
✅ Controlled Re-enrollment
Re-enrollment criteria rely on track_state = Active, ensuring contacts rejoin at the correct position. The system validates state before any re-enrollment.
🛡️ Prevents Common Issues
This design prevents duplication, looping, or premature restarts of nurture sequences. Contacts receive the right message at the right time without repetition.
